多栏正文是一个文本框，分栏由阅读器自己完成

CSS 的 columns 在 PowerPoint 里有原生对应物：正文设置里的栏数。文字仍然是一个可编辑的文本框，改动之后会自己重新分栏，而不是被切成两个互不相干的框。

两栏排版在长文里最有用：一段连续的正文被分成等高的两栏，读者的视线从上到下、再从左到右，行宽保持在舒适的范围里，而整块文字仍然是一次连续的阅读。

这条规则被译成一个设置了栏数的正文框，栏间距离来自 column-gap。之所以能这样做，是因为两边的模型本来就一致：浏览器把行框排进栏，PowerPoint 把段落排进栏，两者都在编辑时重排。

高度是均衡的：盒子按“总行数除以栏数向上取整”预留，所以两栏的最后一行基本落在同一水平线上，而不是把第一栏填到底、再让第二栏孤零零地剩下几个字。

能这样翻译的前提是被分栏的块里只有纯文本。如果一个子元素自己带背景、边框或内边距，分栏就会把这些装饰切断，那种情况仍然上报，而不是画错了再说。

行内语义仍然保留：加粗、斜体、等宽代码 都会跟着文字一起进栏，因为它们在文本框里本来就是一段段带格式的 run，而不是三个独立的文本框。

栏数也有上限。正文宽度有限，栏数越多每栏越窄，中文的行长会短到频繁换行；两栏到三栏是幻灯片上比较稳妥的区间，再往上通常应该换一页。

如果设计真的需要每一栏有自己的底色，那它其实是三张并排的卡片，而不是一段分栏的正文——用 flex 或 grid 表达，比把背景塞进分栏里更接近原意。

三栏用于更细的对照：字号更小、行距更紧，适合放并列的说明、术语表或者多条短注。

栏数不是越多越好。超过三栏之后，中文的行长会短到频繁换行，阅读反而变慢。

栏间距要跟着字号走：正文十三像素时，四十四像素的栏间距差不多是一行的两个汉字宽。

这一段用来把第三栏填满，让三栏的高度看起来接近，也顺便验证行数除不尽时向上取整的行为。

每一栏的宽度由总宽度减去栏间距再均分得到，栏间距会按栏数从总宽度里扣掉，所以三栏不会比两栏更宽。

截断、悬挂标点这些文字层面的规则在分栏里同样生效，因为它们作用在行上，而栏只是一条更短的边界。
